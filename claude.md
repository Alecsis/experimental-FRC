## 📐 Architecture Rules
*Full rationale, sanctioned exceptions, and decision history: `docs/claudex/architecture.md`.*

1. **Strict Hardware Isolation:** No vendor hardware APIs (CTRE Phoenix, REVLib, etc.) are allowed in standard subsystem files. They must live strictly inside `*IOReal.java` implementations, or inside `utility/RobotMotor.java` — a shared TalonFX construction/telemetry wrapper instantiated only from `*IOReal.java` files, not a new hole in the boundary (see `docs/claudex/design/robotmotor-refactor.md`). Sanctioned exception: `subsystems/CommandSwerveDrivetrain.java` / `utility/simulation/MapleSimSwerveDrivetrain.java` (CTRE Tuner X generated output — see `docs/claudex/architecture.md` for why).
2. **Singleton Subsystems:** Every subsystem and the `Superstructure` must implement the Singleton pattern (`private` constructor and `public static Subsystem getInstance()`).
3. **Centralized States:** The `Superstructure` coordinates complex multi-subsystem states via a `SuperstructureState` enum (`OFF`, `INTAKING`, `EJECTING`, `STOWED`, `ALIGNING`, `SHOOTING`) and a `periodic()` switch-case that commands Shooter/Intake/Vision directly — the arbitration logic lives in `periodic()`, not in composed Commands. `shootCmd()`/`shootingSequence(double)` are thin Command bridges only, kept because `RobotContainer`'s `whileTrue` binding and PathPlanner's NamedCommands require real Command objects.

## 🧠 Karpathy Guidelines (Anti-Failure Mode Protocol)
To ensure elite execution, strictly adhere to these behaviors:
- **No Assumptions:** Never guess vendor API syntax or class constructor shapes (especially Phoenix 6 vs 5). Stop and use `context7` or web search to verify the real-world signature first.

## 📝 Session Lifecycle Commands (`/bootstrap`, `/recap`, `/tldr`)
Three slash commands bracket the workflow. Each has its full definition in `.claude/commands/`.

**`/bootstrap` — Rebuild context after a compaction or new session (read-only).** Its only job is context rebuild — not a recap, not a history re-read. Reads, in order: `CLAUDE.md` (including its `## Session Handoff` pointer) → the latest session note it points to → that note's `## Handoff` section specifically → `docs/claudex/architecture.md` only if referenced → `docs/claudex/verification-loop.md` only if relevant → `docs/claudex/history.md` only if the handoff genuinely isn't enough. Reports current objective, branch/state, verified facts, remaining unknowns, and next safe action, then stops and waits — never edits a file, never starts implementing. See `.claude/commands/bootstrap.md`.

**`/recap` — End-of-session sync, local only.** When the user invokes it:
1. Gather evidence from git/status/tests before writing anything — no writing from memory of the conversation alone.
2. Zero-work guardrail: if nothing changed and no hypothesis was confirmed/disproven, report that and stop — do not fabricate progress or refresh the verified line just to look busy.
3. Update this file's **Current Task State** (`Next up`/`Backlog` only — `Done` lives in `docs/claudex/history.md`) with current state, blockers, and next safe action, and refresh the verified-tree line.
4. Append finished work to `docs/claudex/history.md`, with file paths and verification evidence.
5. If a session establishes or revises an architecture decision, update `docs/claudex/architecture.md`.
6. Create or append today's session note at `docs/claudex/sessions/YYYY-MM-DD.md` (what changed, why, verification performed, remaining unknowns, next safe action, and a `## Handoff` block), and point this file's `## Session Handoff` section at that note's path.

`/recap` never touches the Obsidian vault. See `.claude/commands/recap.md`.

**`/tldr` — Weekly knowledge sync into the Obsidian vault (run periodically, not every session).** Reads `CLAUDE.md`, `docs/claudex/history.md`, `docs/claudex/architecture.md`, and the accumulated `docs/claudex/sessions/` notes, and promotes only durable knowledge — tuned gains, hardware discoveries, architecture lessons, best practices, recurring debugging patterns, confirmed/disproven hypotheses — into the matching Obsidian topic notes. Consolidates duplicate conclusions across sessions; leaves temporary task status and session chatter behind. `/recap` logs today locally; `/tldr` is the only command that writes to the vault. See `.claude/commands/tldr.md`.
