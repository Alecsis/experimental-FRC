## Why it changed

Continues directly from `CLAUDE.md`'s "corrected fix order" (SysId → drive `Slot0` → chassis PID), the standing
next-priority item on the robot-code stack since the VT-input-relay migration arc closed at the end of the thirtieth
session. The mentor's first request this session — "a complete SysId/Slot0 retuning audit" — surfaced a fact that
fix order didn't account for: autonomous path-following runs `OpenLoopVoltage`, which never consults `Slot0` at all,
meaning that established fix order was never going to address the specific tracking-error problem it was written
for. Each subsequent mentor request (re-verify with a full call graph; compare the two architectures fairly; design
a migration plan; scope Phase 1 to simulation) was a deliberate step of confirming that finding thoroughly enough to
act on before committing engineering time to a real architecture change.
