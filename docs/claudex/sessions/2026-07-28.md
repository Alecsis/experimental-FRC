1. **`"Orbit"` had no timeout.** `RobotContainer.java` registered `drivetrain.trackHub(vision, 0, () -> 0, () -> 0,
   true)` with no bound. It sits inside `parallel(Orbit, Shooting Sequence)` (or `Quick Shooting`) at the end of

   failure to converge would silently hang the entire auto forever. This exact risk was already flagged in

   `.withTimeout(2.0)` added to the registration, plus a new `RobotContainer.BOUNDED_NAMED_COMMANDS` allowlist.
2. **`Superstructure.shootingSequence(double)` had an empty Command-requirement set.** Unlike `shootCmd()`/
   `intakeCmd()`/`ejectCmd()`/`stowCmd()` (all of which declare `this`), its composing `Commands.runOnce(...)`/
   `Commands.waitUntil(...)` took no subsystem argument. A live SmartDashboard button (`"State: Shoot"`/`"State:
   Eject"`/etc., clickable via NetworkTables in any robot mode including autonomous) pressed mid-auto would not
   cancel the running NamedCommand step, letting both write `mWantedState` concurrently. Fixed: one-argument change,
   `Commands.runOnce(() -> requestShoot(timeoutSeconds), this)`.
