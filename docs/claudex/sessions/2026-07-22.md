## Why it changed

The mentor, having confirmed the supervisor works end-to-end, wants the terminal experience as
close to native Claude Code as possible and asked for a root-cause investigation of the four gaps
above before any fix — explicitly: identify whether each is caused by pywinpty limitations,
ConPTY behavior, missing event forwarding, console-mode configuration, or the supervisor's own

Used the `systematic-debugging` skill. Went past reading `pty_session.py`/`run.py` alone: read the

Findings by confidence:
1. **Resize (high confidence, confirmed):** `PtySession.start()` sizes the inner ConPTY once at
   spawn; a working `setwinsize(rows, cols)` method exists in pywinpty but was never called.
2. **Scrollback (medium confidence, hypothesis):** likely downstream of #1 — Claude's own
   cursor-redraw math for its compose box runs against a stale size, corrupting what's on screen.
   Recommended retesting after #1's fix rather than building a second fix blind.
3. **Mouse selection (low-medium confidence):** ConPTY doesn't touch the outer console's mode, and
   the passthrough is byte-for-byte faithful, so this may not be a supervisor bug at all —
   recommended a Shift+drag test plus a native-`claude` baseline before assuming anything's broken.
4. **Ctrl+Tab (high confidence on structural cause, medium on which applies):** `msvcrt.getwch()`
   structurally can't carry modifier state beyond the hardcoded `_SPECIAL_KEYS` table; separately,
   Windows Terminal's default `ctrl+tab` = next-tab keybinding may eat the keystroke before the
   app ever sees it. Recommended checking for a visible tab-switch in WT before considering the
   `ReadConsoleInputW` input-loop rework that would fix the `msvcrt` gap.

Asked the mentor which terminal hosts `run.py` (materially affects #2/#3's confidence) — answered
Windows Terminal, sharpening the Ctrl+Tab and mouse-selection hypotheses. Presented a phased plan;
mentor approved starting with #1 only, holding #2–#4 for live checks first.

Implemented #1 via TDD: wrote `test_pty_resize.py` first, watched it fail
